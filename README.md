SOLAD generates synthetic **global horizontal irradiance (GHI)** sequences at **10-minute resolution** from a site's latitude, longitude, and date range alone. It does not require concurrent meteorological observations, local calibration, or site-specific measurements at inference time.

**Maintainer and designer:** Azeddine Frimane

## Overview

Solar irradiance data is essential for photovoltaic yield assessment, storage sizing, grid integration, ramp-event analysis, probabilistic forecasting, and renewable-energy planning. High-quality ground measurements, however, are sparse and unevenly distributed. SOLAD addresses this gap with a physics-guided two-stage latent diffusion model that learns atmospheric variability from measured irradiance while calculating the deterministic solar envelope directly from location and date.

The model separates what is known from physics from what must be learned from data:

- **Solar geometry and clear-sky irradiance** are computed deterministically with `pvlib`.
- **Cloud-driven variability** is represented through the clear-sky index.
- **Daily irradiance profiles** are compressed into compact latent fingerprints by a deterministic physics-conditioned convolutional autoencoder.
- **Multi-day weather dynamics** are generated by a Transformer diffusion model in a transformed latent space.
- **Nighttime values and physical bounds** are enforced by the generation pipeline.

The result is a reusable generator for synthetic sequences of arbitrary length, including locations that were not present in the training set.

## Scientific contributions

1. **Coordinates-and-date-only inference.** The released inference path needs latitude, longitude, and a date range. It does not consume concurrent weather measurements or satellite imagery.
2. **Physics-guided daily decoding.** Solar zenith, extraterrestrial irradiance, clear-sky GHI, and the sunlit mask condition the decoder at every intraday step.
3. **Clear-Sky Log Transform.** The bounded latent representation is mapped into a normalized logarithmic optical-depth domain motivated by Beer-Lambert attenuation. In the implementation, this functionality is provided by `LatentTauTransform` in `solar_diffusion/optical_depth.py`.
4. **Four-class regime conditioning.** A data-driven taxonomy represents clear, mixed-clear, mixed-overcast, and overcast days and supplies an interpretable conditioning signal to the diffusion model.
5. **Arbitrary-length generation.** Overlapping latent windows and context conditioning allow sequences longer than one model window to be generated autoregressively.
6. **Sub-hourly variability.** The 10-minute representation is designed to retain within-day cloud transitions, ramp events, and temporal structure relevant to planning and grid studies.

## Local installation

### Requirements

- Python 3.10 or newer.
- A CPU for short requests; CUDA is recommended for longer generation ranges or training.
- The packages listed in `requirements.txt`.

### Environment setup

Run these commands from the repository root:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

For a CUDA-enabled installation, install the PyTorch build matching the local CUDA version before installing the remaining requirements.

### Run the Streamlit application

```bash
. .venv/bin/activate
streamlit run app.py
```

The app performs a startup artifact check and loads the released inference bundle from paths relative to the repository root. Do not rename or move those files unless the paths in `app.py` and `config.yaml` are updated as well.

## Architecture

### 1. Physics preprocessing

For each requested day and location, `pvlib` calculates solar position and clear-sky irradiance. The model uses a deterministic intraday physics vector:

```text
[solar zenith angle, extraterrestrial irradiance, clear-sky GHI]
```

The sunlit mask is derived from solar zenith. Nighttime values are excluded from the clear-sky-index representation and are restored as exact zeros in the final daily profile.

### 2. Clear-sky index representation

For sunlit timesteps, the clear-sky index is formed from measured or generated irradiance relative to clear-sky GHI. The implementation uses a configured upper bound of `k_max = 1.30`, allowing moderate circumsolar enhancement above unity while limiting extreme values.

The clear-sky index isolates the atmospheric and cloud contribution from the deterministic solar envelope. The latent optical-depth transform then provides the additive representation used by Gaussian diffusion.

### 3. Physics-conditioned daily autoencoder

`SolarVAE` in `solar_diffusion/vae.py` compresses each variable-length sunlit daily profile into:

- A primary latent fingerprint for the daily irradiance shape.
- A variability component for intraday character.
- A decoder output conditioned on deterministic intraday physics.

The decoder is generation-safe: at inference it receives only generated latent values and deterministic solar physics, not observed cloud or irradiance channels.

### 4. Latent Transformer diffusion

`SolarDenoiser` in `solar_diffusion/denoiser.py` generates windows of consecutive daily latent vectors. It is conditioned on:

- Continuous location features using sine and cosine encodings of latitude and longitude.
- Day-level solar geometry and climate features.
- Intraday physics embeddings.
- Four fitted sky-regime classes.
- Classifier-free guidance during sampling.

### 5. Long-sequence generation

`generate_sequence` in `solar_diffusion/generate.py` creates one or more overlapping windows. Context overlap is carried into subsequent windows, and the decoded profiles are blended at boundaries. This allows the application to generate date ranges longer than the model's native 14-day window.

## Programmatic inference

The primary programmatic entry point is:

```python
from solar_diffusion.generate import generate_sequence
```

It accepts the requested date range, coordinates, loaded model objects, normalization artifacts, and the configuration dictionary. `app.py` is the reference for loading the models and constructing the required runtime objects.

The generated internal representation is a clear-sky-index sequence. The application converts it to GHI using the calculated clear-sky irradiance and exports the following fields:

- Date.
- Timestep.
- Generated GHI.
- Clear-sky GHI.
- Solar zenith.

## Training and fine-tuning

The training pipeline has two stages.

### Stage 1: daily autoencoder

1. Prepare daily profiles from SURFRAD or another irradiance dataset.
2. Compute solar geometry and clear-sky irradiance with `data/preprocessing.py` and `data/physics_utils.py`.
3. Fit intraday and day-level normalization statistics.
4. Fit the four-class regime model.
5. Train `SolarVAE` using the reconstruction, spectral, ramp, curvature, separation, and latent-variance objectives.

### Stage 2: latent diffusion

1. Encode daily training profiles with the frozen autoencoder.
2. Fit `LatentTauTransform` on the latent cache.
3. Train `SolarDenoiser` on overlapping day windows in transformed latent space.
4. Save the diffusion checkpoint, transform statistics, regime artifacts, and training logs.

### Configuration checks

Before training, verify:

- `data.augmentation.k_max_clip == physics.k_max`.
- `diffusion.n_regimes == data.regime.n_components`.
- `diffusion.n_ctx_train == data.window_size - inference.stride`.
- The diffusion regime-weight list has one value per regime.
- The VAE regime-weight list has one value per regime.

The released inference bundle is ready for application use. Obtain raw SURFRAD station data from the [NOAA SURFRAD archive](https://gml.noaa.gov/grad/surfrad/).

## Reproducibility notes

- The model operates at 10-minute resolution with 144 full-day timesteps.
- The default diffusion model uses 14-day windows and a stride of 5 days during inference.
- The default generation limit exposed by the application is 365 days per request.
- Randomness enters latent sampling and can produce different valid sequences for the same location and dates.
- The released model is a pooled North American model and is not calibrated independently for every target site.
